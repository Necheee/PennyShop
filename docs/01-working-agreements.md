# Working Agreements & Project Rules

This document outlines the strict working agreements for the PENNY website front-end implementation. It serves as the single source of truth for anyone contributing to the project.

## 1. Strict Adherence to Decisions
The owner has made every design and technical decision. These are **locked** and must not be revised without explicit permission.

**Do not change the following without the owner's explicit approval:**
- The tech stack, or adding/removing/upgrading any dependency or library.
- The colour palette, typography, spacing system, animation rules, or any visual design decision.
- The page list, routes, category and subcategory structure, folder structure (including the `client` and `server` split), or data model.
- Brand copy, policy copy, and the text of any announcement.
- The logo (never redraw, recolour, crop, or "improve" it).
- Features: do not add, remove, or reduce them.

## 2. Proposing Changes
If a change is deemed necessary or if something is ambiguous:
1. **Stop work** on that item immediately.
2. **Tell the owner** what needs to be changed, why, and present the alternatives.
3. **Wait for a clear "yes"** before touching anything. Silence is not permission. Do not guess.

## 3. The Checkpoint Rule
Work must be completed in the defined phases (see `04-phases-and-status.md`). At the end of each phase, the developer must **stop and report**:
- What was built.
- Which files were created or changed.
- Anything that deviated from the original plan (there should be nothing without prior approval).
- Any open questions.

**Do not start the next phase until the owner approves the current one.**
